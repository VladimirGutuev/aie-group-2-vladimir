# Отчёт по итоговому проекту: Smart Parking ANPR

## 1. Паспорт проекта

- **Название проекта:** Smart Parking ANPR — сервис автоматического распознавания автомобильных номеров для систем контроля доступа (СКУД)
- **Автор:** Гутуев Владимир Евгеньевич
- **Группа:** БФБО-01-24
- **Контакт:** @Gutuevv, vgutuev@gmail.com
- **Ссылка на репозиторий:** https://github.com/VladimirGutuev/aie-group-2-vladimir

Проект — REST API-сервис, который по изображению номерного знака возвращает распознанный
текст и уверенность модели. Решение строится как двухступенчатый пайплайн (детекция области
номера → OCR) и сравнивает три подхода к OCR: готовый general-purpose EasyOCR (baseline),
собственную обученную модель CRNN и production-референс Nomeroff Net. Цель по качеству —
Full Sequence Accuracy (FSA) > 85% — достигнута с большим запасом (99.5%).

---

## 2. Постановка задачи и контекст

**Предметная область.** Автоматизация контроля доступа на парковки ЖК и бизнес-центров.
Пользователь — служба охраны; сервис заменяет ручной ввод номеров и ускоряет пропуск машин.
Сценарии: умный шлагбаум, безбилетные парковки ТЦ с автосписанием, журнал въезда/выезда на
охраняемых объектах.

**Формулировка в терминах ML.**
- Вход: изображение номерного знака (кроп) или кадр с камеры.
- Выход: строка номера (последовательность символов) + уверенность.
- Тип задачи: распознавание последовательности символов (sequence recognition / OCR).

**Целевые метрики.**
- **Full Sequence Accuracy (FSA)** — доля номеров, распознанных полностью верно (все символы).
  Это основная бизнес-метрика: для СКУД важен корректный номер целиком, одна ошибка = неверный пропуск.
- **Character Error Rate (CER)** — нормированное редакционное расстояние; вспомогательная метрика,
  показывает «насколько близко» при неполном совпадении.
- **Эффективность** (параметры, размер, latency) — важна для edge-развёртывания на камере/шлагбауме.

Целевой порог: **FSA > 85%**.

## 3. Данные

**Источник.** [AUTO.RIA Numberplate OCR RU](https://nomeroff.net.ua/datasets/) (датасет проекта
Nomeroff Net) — открытый набор кропов российских автомобильных номеров с текстовой разметкой.

**Структура.** Стандартная разбивка `train / val / test`, в каждой — `img/*.png` (кропы) и
`ann/*.json` (поле `description` = текст номера латиницей).

| Split | Изображений |
|-------|-------------|
| train | 49 382 |
| val   | 4 893 |
| test  | 2 845 |

**EDA** (`notebooks/01_eda.ipynb`): распределение длины номеров (8–9 символов), алфавит из 22
символов (`0123456789ABCEHKMOPTXY` — латинские эквиваленты букв РФ-формата), разброс размеров
кропов (часть мелкие — мотивация апскейла в препроцессинге).

**Предобработка.**
- Нормализация номера (`src/postprocess.py`): верхний регистр, транслитерация кириллических
  look-alike символов в латиницу (А→A, В→B, …), отбрасывание не-алфавитно-цифровых.
- Для CRNN: grayscale, ресайз до 32×128, нормализация в [0,1].

## 4. Модели и подходы

### 4.1. Baseline — готовый EasyOCR

General-purpose OCR без дообучения. Прогон по кропу + три варианта улучшения (ablation):
1. «как есть»;
2. + препроцессинг (grayscale, апскейл, CLAHE) и allowlist символов РФ-формата;
3. + позиционная постобработка по маске номера `Б ЦЦЦ ББ ЦЦ(Ц)` (исправление путаницы
   `0↔O, 7↔Z, 5↔S` по позициям).

Реализация: `src/models/ocr.py`, `src/evaluate.py`.

### 4.2. Собственная модель — CRNN + CTC

Классическая архитектура для OCR: CNN-бэкбон → BiLSTM → CTC-декодирование (`src/models/crnn.py`,
обучение `src/train_ocr.py`). Обучена на train-сплите (49k), 15 эпох, Adam, batch 256.

Обучены два варианта:
- **CRNN-full** (5.31M параметров): максимум точности.
- **CRNN-tiny** (1.95M параметров): 1 LSTM-слой, hidden 128 — минимум размера для edge.

### 4.3. Reference — Nomeroff Net OCR

Готовая production-модель распознавания РФ-номеров (`src/eval_nomeroff.py`). Использована как
верхняя планка качества. Интеграция потребовала обхода несовместимостей версий (см. §7).

### 4.4. Детектор номера — YOLOv8n

Первая ступень пайплайна: находит область номера на полном кадре (`src/train_detector.py`,
данные — `src/data/prepare_detector.py`). Обучен на открытом датасете детекции номеров
(keremberke, ~8.8k изображений, конвертированных в YOLO-формат: train 6176 / val 1765 / test 882),
40 эпох на RTX 3050. Для детекции страна номера не важна — модель учится находить прямоугольник
знака, а чтение выполняет CRNN.

## 5. Экспериментальный протокол и результаты

**Протокол.** Все модели оценены на **одном и том же test-сплите (2845 изображений)**, метрики
считаются единым кодом (`levenshtein` + нормализация номера), что обеспечивает честность сравнения.
Обучение/инференс — на NVIDIA RTX 3050 (8 ГБ).

### 5.1. Точность

| Модель / конфигурация | FSA | CER |
|---|---|---|
| EasyOCR, как есть | 0.068 | 0.482 |
| EasyOCR + препроцессинг + allowlist | 0.096 | 0.323 |
| EasyOCR + RU-постобработка | 0.220 | 0.281 |
| **CRNN-full (наша)** | **0.9954** | 0.0006 |
| CRNN-tiny (наша) | 0.9866 | 0.0018 |
| Nomeroff Net (reference) | 0.9958 | 0.0005 |

**Вывод по точности:** general-purpose EasyOCR на номерах непригоден (22% даже после доменной
постобработки) — задача требует специализированной модели. Наша CRNN-full (99.54%) практически
сравнялась с production-референсом Nomeroff (99.58%) — разница в 1 номер из 2845.

### 5.2. Эффективность (RTX 3050 + CPU)

| Метрика | CRNN-full | CRNN-tiny | Nomeroff |
|---|---|---|---|
| Параметры | 5.31M | **1.95M** | 3.47M |
| Размер весов | 21.2 МБ | **7.8 МБ** | ~14 МБ |
| CPU latency (1 img) | 6.24 мс | **4.10 мс** | 4.73 мс |
| GPU latency (1 img) | 2.06 мс | **0.80 мс** | — |
| test FSA | 0.9954 | 0.9866 | 0.9958 |

**Вывод по эффективности:** CRNN-tiny **превосходит Nomeroff по компактности (в 1.8× меньше
параметров и размера) и по single-image latency** при сохранении точности 98.66% (кратно выше
целевых 85%). Это значимо для edge-сценариев СКУД, где кадры обрабатываются по одному, а размер
модели важен для встраивания в камеру/контроллер.

### 5.3. Детектор номера (YOLOv8n)

| Метрика (test) | Значение |
|---|---|
| Precision | 0.987 |
| Recall | 0.953 |
| **mAP@50** | **0.991** |
| mAP@50-95 | 0.713 |

Детектор уверенно локализует номера (mAP@50 = 0.99). End-to-end проверка (полный кадр → детектор →
crop → CRNN) подтверждает работу всего пайплайна: на кадре находятся 1–2 номера, каждый передаётся
в OCR. Замечание: сквозная точность текста максимальна на РФ-кадрах (под них обучена CRNN); на
кадрах других стран детектор находит номер, но чтение ограничено РФ-алфавитом CRNN.

### 5.4. Выбор финальной модели

**Финальная модель — CRNN-full** как движок сервиса по умолчанию: максимальная точность (99.54%),
на уровне production-референса, при простоте развёртывания (один файл весов 21 МБ, зависимости
только `torch + opencv`). **CRNN-tiny** предлагается как edge-вариант (флаг `CRNN_WEIGHTS`) когда
критичны размер и скорость. EasyOCR оставлен как baseline для воспроизведения сравнения.

Обоснование: при паритете точности с Nomeroff наше решение радикально проще в установке
(Nomeroff тянет `pytorch_lightning`, `turbojpeg`, `modelhub_client`, CRAFT и конфликтует с
актуальными версиями torch/numpy — см. §7), а tiny-вариант ещё и эффективнее по ресурсам.

## 6. Архитектура решения и сервис

**Пайплайн** (`src/pipeline.py`): детектор области номера (опционально, `USE_DETECTOR`) → кроп →
OCR-движок (выбирается через `OCR_ENGINE`: `crnn` | `easyocr`) → нормализация → результат.

**API** (`src/service/app.py`, FastAPI):
- `GET /health` — health-check;
- `GET /metrics` — счётчики запросов/ошибок (наблюдаемость);
- `POST /predict` — изображение (multipart) → `{plate, confidence, detections[]}`.

**Стек:** Python 3.11, PyTorch (CUDA 12.1), FastAPI/uvicorn, OpenCV, EasyOCR (baseline),
Ultralytics YOLOv8 (детектор). Контейнеризация — `Dockerfile`. Конфигурация — `pydantic-settings`
(`.env` / `configs/`).

---

## 7. Наблюдаемость, конфигурация и безопасность

**Логи/наблюдаемость:** структурное логирование запросов и ошибок (`logging`), эндпоинты
`/health` и `/metrics` (счётчики `requests_total`, `predict_total`, `predict_failed`,
`plates_recognized`).

**Конфигурация:** все параметры (движок OCR, веса, языки, порог, GPU, детектор) вынесены в
переменные окружения / `configs/`; `.env.example` как шаблон, реальный `.env` в `.gitignore`.

**Безопасность:** в репозитории нет секретов и персональных данных; используется только открытый
датасет с атрибуцией. Веса моделей — собственные (обучены в проекте).

**Заметка о совместимости (честный инженерный опыт).** Интеграция Nomeroff Net 4.0.1 потребовала
обхода четырёх несовместимостей с актуальным окружением (Windows, torch 2.12):
`modelhub_client` (нет на PyPI → установка из git), `turbojpeg` (conda-forge), `weights_only`
по умолчанию в torch ≥2.6 (патч `torch.load`), и баг их API — `TextDetector.predict` передаёт
сырые зоны в OCR, ожидающий препроцессированный тензор (патч). Это подтверждает практическую
ценность нашего лёгкого решения с минимумом зависимостей.

## 8. Ограничения и дальнейшая работа

- **Сквозной домен:** детектор обучен на мультистрановом датасете, CRNN — на РФ-номерах. Для
  максимальной end-to-end точности на РФ нужен набор полных РФ-кадров с текстовой разметкой
  (текущие РФ-данные — только кропы).
- **Режим по умолчанию:** сервис стартует в режиме кропа (`USE_DETECTOR=false`); полный кадр
  включается флагом `USE_DETECTOR=true`.
- **Дальше:** SVTR как ещё более точная OCR-модель, Prometheus-метрики, аугментации для
  устойчивости к грязи/наклону/ночной съёмке, дообучение под РФ полные кадры.

## 9. Сценарий демонстрации на защите

1. Запустить сервис: `python -m uvicorn src.service.app:app --reload` (движок CRNN по умолчанию).
2. В Swagger UI (`/docs`) отправить 2–3 кропа номеров в `POST /predict` — показать корректный
   распознанный номер и уверенность.
3. Показать `notebooks/01_eda.ipynb` (EDA) и таблицы §5 (сравнение точности и эффективности).
4. Подчеркнуть ключевой результат: своя CRNN на уровне production-Nomeroff (99.5%), а tiny-вариант
   превосходит его по компактности и скорости.
